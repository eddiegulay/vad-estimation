# VAD Models — Roadmap

Training pipeline for lightweight, real-time VAD models. First architecture: a CRNN in the Silero-VAD shape (Conv1d-DFT frontend + depthwise-separable convs + 1 GRU, ~150-310K params), built through a config-driven, multi-architecture pipeline so a MarbleNet-style TCN and/or an FSMN-style model can be trained later without restructuring. Full design rationale lives in the approved plan at `/Users/eddiegulay/.claude/plans/structured-mapping-dream.md`.

## Decisions Log (append-only, dated)
- 2026-08-07: Added `onnx` and `onnxscript` as dependencies (not anticipated in the original plan) — PyTorch 2.13's `torch.onnx.export` requires both regardless of the legacy-vs-dynamo exporter path chosen. Both have working Python 3.14.4 arm64 wheels.
- 2026-08-07: ONNX export targets opset 18, not 17 — the reflect-pad op used by the frontend's context-assembly step has no opset-17 version-converter adapter in this onnx/onnxscript release; requesting 17 only produced a harmless-but-noisy fallback warning.
- 2026-08-07: Chose CRNN (Silero-shape) as the first architecture over a pure separable-conv TCN and an FSMN-style memory-block model, based on best proven accuracy-per-parameter at this budget; TCN is the designated fast-iterating fallback/comparison arm.
- 2026-08-07: Interval-list label representation `(start_s, end_s, label)` chosen over dense per-frame arrays — hop-agnostic, so one manifest serves every future architecture regardless of its frame hop.
- 2026-08-07: Augmentation (noise mix, reverb, concatenation) assembled on-the-fly in DataLoader workers, never pre-rendered to disk — avoids disk blowup and increases effective data diversity across epochs for a small (~40h) corpus.
- 2026-08-07: Mel/spectrogram features computed inside the model as a Conv1d-DFT frontend (first layer), not precomputed/cached — guarantees train/inference parity and keeps ONNX export raw-waveform-in.
- 2026-08-07: Dropped `torchaudio` as a dependency — the architecture avoids `torch.stft`/complex tensors by design, and `scipy.signal.resample_poly` covers the one offline resampling need (ESC-50 44.1kHz→16kHz), avoiding an unvalidated torch/torchaudio version-compatibility surface on Python 3.14.4.
- 2026-08-07: AMI split at the meeting level only; `EN2001a` (the only genuinely spontaneous meeting) routed to validation, not train.
- 2026-08-07: FLEURS Swahili used only as a cross-lingual sanity-eval set (`sanity_fleurs.jsonl`), structurally prevented from ever entering the training split.

- **Resolved**: full training throughput, confirmed via the real `crnn_v1_full`/`tcn_v1_full` runs — steady-state per-epoch time is ~100-250s for both architectures (146 train steps + 9 val batches at batch_size=64), not the runaway slowness suspected from the incomplete in-session smoke attempt. Occasional spikes to 300-700s were observed and traced to concurrent system load (Docker Desktop's Linux VM, Electron apps) via `ps`/`top`, not a code or MPS issue — confirmed no thermal throttling (`pmset -g therm`) and the training process's own CPU time kept climbing normally throughout. No further tuning needed.
- **Resolved**: the one-time-warmup signal noted from early smoke runs (first train step/val batch ~9-10s, later ones ~1-1.5s) is real but small relative to a full epoch (146 steps) — not worth optimizing further.
- **`caffeinate` "ClientDied" incident**: the first `train.sh` run launched via the harness's tracked background-task mechanism was killed ~2.5h in, right as `crnn_v1`'s 50th epoch finished (before evaluate/export could run). `pmset -g log` confirmed zero system sleep/wake events occurred — the kill came from the background-task's own lifecycle, not macOS sleep (so `caffeinate -dims` was not the problem; something external to the OS terminated the tracked process). No data was lost (`best.pt`/`last.pt` are saved every epoch), but re-running `train.sh` as originally written would have blindly retrained CRNN from scratch. Fixed two things: (1) `train.sh`'s training steps now go through `train_or_skip`, which skips training for a run whose `best.pt` already exists (override with `FORCE_RETRAIN=1`), making the script safely resumable mid-pipeline; (2) relaunched via `nohup ./train.sh & disown` instead of the harness's tracked background-task mechanism, fully detaching the process from this session so a similar external kill can't recur. The resumed run completed cleanly end to end.
- **Fixed**: `train.sh` had a real bug (`"${EPOCH_ARGS[@]}"` under `set -u` with an empty array) that made every run fail immediately at the CRNN training step with "unbound variable" — a known macOS bash 3.2 quirk (empty-array `[@]` expansion errors under `set -u` in bash <4.4). Fixed with the `${EPOCH_ARGS[@]+"${EPOCH_ARGS[@]}"}` idiom, which correctly expands to zero arguments when the array is empty instead of erroring or (as a naive `:-` fallback would) passing a stray empty-string argument that broke `argparse`.
- Training throughput on MPS was slow for long sequences (~0.4-0.9s/optimizer step observed initially, e.g. AMI's 20s windows and LibriSpeech-concat examples up to ~60s) — likely `nn.GRU` per-timestep dispatch overhead on the MPS backend rather than a fused kernel. **Resolved in Phase 6**: `Trainer` now random-crops training sequences to `max_train_duration_s` (default 10.0s, `configs/train/default.yaml`) before the forward pass — eval/inference still see full sequences. This dropped per-step time to ~0.16s (150 steps in 24.5s). Revisit the crop duration once real training results are in — 10s may be too short to capture the longer pauses the synthetic-concat recipes generate.
- Most AMI meetings are scripted/acted role-play; only `EN2001a` is genuinely spontaneous — held out for validation accordingly.
- AMI per-meeting speech occupancy (union of all near-field channels) runs 62-92% across all 33 meetings, well above the plan's 0.20-0.80 "manual review" band for ~19 of 33 meetings. Investigated and accepted as expected, not a bug: unioning speech across 4 simultaneous speakers in an interactive meeting means someone is talking most of the time. All 33 meetings pass a broader 0.05-0.95 automated sanity guard (`tests/labels/test_ami.py::test_ami_meeting_speech_occupancy_sanity`).
- Training data kit is modest (~40h total, ~19h real conversational audio) relative to production VAD training sets (e.g. NeMo MarbleNet v2: ~3900h) — expectations are calibrated to "a competent from-scratch model," not "beats Silero outright."
- ESC-50 is CC BY-NC (non-commercial only); swap to MUSAN/FSD50K if this ever needs a commercial license.
- Aachen AIR RIR database licence is unstated; swap to RIRS_NOISES (SLR28) if this ever needs a commercial license.

- 2026-08-07: TCN's ONNX export uses a fixed batch size of 1 (not a dynamic axis like CRNN's export) — the exporter's `dynamic_axes`-to-`dynamic_shapes` conversion failed on TCN's per-block state tensors (differing trailing dims per dilation level). Accepted: streaming VAD inference is batch=1 in practice anyway.
- 2026-08-07: Chose per-layer activation-cache streaming state for TCN (`CausalDepthwiseSeparableBlock.forward_step`, one small buffer per temporal block) over a simpler "recompute the receptive-field window from raw audio/embeddings" approach — the simpler approach was tried first and found to NOT exactly reproduce `forward_full` (diffs up to ~0.3 in early testing): feeding zero-valued inputs through an earlier layer's bias produces non-zero output, so re-deriving a later layer's boundary from that diverges from `forward_full`'s independent per-layer zero-padding convention. Per-layer caching sidesteps this and is also O(1)/step instead of O(receptive field). Verified to float-precision parity (diff ~7e-7) before adopting.
- 2026-08-07: `crnn_v1_full` chosen as the stronger candidate over `tcn_v1_full` for future work, despite TCN reaching a higher raw val_f1 during training (0.79 vs 0.73) — CRNN wins on TEN AUROC (0.905 vs 0.888), RTF (0.0062 vs 0.0298, ~5x cheaper), and calibrated F1 (0.9466 vs 0.9421). TCN's higher val_f1 appears to reflect better fit to the val split specifically rather than better generalization to TEN's held-out real-world audio.
- 2026-08-07: Made `train.sh`'s training steps resumable (`train_or_skip`, skip-if-`best.pt`-exists) rather than adding checkpoint-level mid-epoch resume — simpler, and the failure mode observed (external kill between pipeline steps, not mid-epoch) only needed step-level granularity.
